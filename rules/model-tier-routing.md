# Роутинг модели по тиру + защитная безопасность (v9 F3.1-F3.3, база v8 L1-F2/L1-F4)

Контракт «роль → модель → усилие» — единый источник `docs/agent-registry.md` (сверяется
`scripts/check-plugin-self.sh` раздел 4: модель фронтматтера обязана совпадать с реестром).

## Три тира (v9, решение владельца 2026-09-03)

- **Fable 5.1** — верхний уровень: архитектура, план, детализация, критика, аудит, оценка.
  Рассуждает, но **кода не пишет**: запрет висит на роли (`hooks/checks/role-scope-guard.sh`
  читает тип вызвавшей роли) и покрывает запись через оболочку — прежняя формулировка
  «только читающая роль» была неполной, шесть таких ролей имели доступ к оболочке.
- **Opus 5** — написание кода, и только когда работа расписана: фича, трогающая код, не входит
  в работу без команды проверки. Опора — измерение Anthropic: «performs best when given the
  complete task specification up front».
- **Sonnet 5** — сбор сырья, чтение источников, механические слияния и сортировки.
- **Усилие:** `max` у ключевых ролей (архитектор, кодер, аудитор, критики), **ступень ниже** у
  рутинных. Решение владельца: экономить надо, но не там, где цена ошибки высока.

Основание для связки — измеренная Anthropic конфигурация «исполнитель Opus 5 с советником
Fable 5.1» как самая точная из проверенных; цитаты — `docs/model-routing-sources.md`.

**Пин проверяется по факту, а не по документу:** `hooks/checks/model-pin-verify.sh` на
PostToolUse(Agent) сверяет модель, на которой субагент реально стартовал, с реестром. Если
движок не сообщает модель — сторож пишет об этом в журнал срабатываний, и пин честно остаётся
дисциплиной, а не выдаётся за замок.

Смена привязки роль→модель — правкой реестра + фронтматтера (одним движением). Это **смена
контракта** (влияет на 100% выводов роли) — перед выкаткой прогон на 1–2 реальных сценариях
(правило dependency-swap; носитель — `hooks/checks/model-swap-guard.sh`).

## Защитная безопасность → Opus, НЕ свежайшая frontier (L1-F4)

Защитную / security-работу — написание security-хуков и защитных гейтов, разбор уязвимостей,
харденинг, анализ вредоносного ввода — роутить на **Opus 5**, а не на свежайшую frontier-модель.

**Почему:** safety-классификаторы самых свежих frontier-моделей склонны отказывать в benign
defensive-security работе mid-task (ложно принимают её за атакующую) — задача обрывается на
середине. Opus стабильно выполняет защитную работу. Урок pilotfish.

**Честная граница (discipline):** надёжного хука на «смысл задачи = security» нет — нельзя
машинно отличить защитную правку от обычной. Носители правила: этот файл + предупреждение
`model-swap-guard` при смене модели + строка в `docs/traceability.md`. Не enforcement-механизм,
а дисциплина; дополняет dependency-swap-контракт.

**Пример из самого плагина:** must-fix L5-F1 (защита границ правок) делался на Opus в main-session,
а не делегировался дешёвому тиру — ровно по этому правилу.
